# Nārada Release Notes — v1.1.0

**Release Tag:** `v1.1.0`  
**Date:** 2026-10-11  
**Milestone:** Workspace Sandboxing, Categorization, Approval Workflows & Multi-Turn Reasoning  

---

## Highlights

### 1. Dedicated Operational Workspace & Sandboxing
- **Strict Confinement:** Nārada's filesystem tools (`filesystem.read`, `filesystem.write`, and the newly added `filesystem.list`) are now strictly confined to the dedicated `workspace/` folder. Any path traversal (`../`) or absolute path pointing outside the workspace boundary is blocked with a descriptive `PermissionError`.
- **Categorized Folder Structure:** Standardized categories are automatically created and initialized:
  - `workspace/documents/` — Written content, notes, drafts, markdown, and documentation.
  - `workspace/code/` — Scripts, automation code, and project files.
  - `workspace/data/` — Datasets, JSON, CSV files, and structured inputs.
  - `workspace/outputs/` — Final deliverables, reports, and generated deliverables.
  - `workspace/temp/` — Transient scratch files.
- **Directory Discovery:** Added `filesystem.list` tool allowing Nārada to explore workspace directory trees safely.

### 2. Human-in-the-Loop Approvals & Governance
- **Interactive Approval Pause:** Consequential write actions pause execution with `PENDING_APPROVAL`, prompt the user with clear context, and hold execution until explicit approval is granted.
- **Multi-Channel Approval:** Approvals can be granted via the `/approve [id]` command, chat response keywords (`"yes"`, `"approve"`, `"proceed"`, `"confirm"`), or the REST API endpoint `POST /v1/approve`.
- **Auto-Approval Flag:** For frictionless local development or automated CI tests, `NARADA_AUTO_APPROVE_WRITES=true` lowers write actions to low risk.

### 3. Multi-Turn Provider Reasoning & Gemini Thinking Models
- **Thought Signature Support:** Full compatibility with Google Gemini 3-series thinking models (`gemini-3.1-flash-lite`). Preserves `thoughtSignature` and `id` across tool turns, allowing reasoning models to execute tools and synthesize answers in a single clean turn without exhausting iteration limits.
- **Message Normalization:** Standardized message normalization across providers to preserve tool metadata (`tool_calls`, `tool_call_id`, `name`) for all OpenAI-compatible and Gemini endpoints.

## Commits & Changes Summary

- `core/config/loader.py`: Workspace auto-detection with fallback to `workspace/`; added `auto_approve_writes`.
- `core/agent/policy.py`: Injected active workspace root into policy and system prompts.
- `core/agent/executor.py`: Added pending action tracking and `execute_pending` execution.
- `core/permissions/engine.py`: Added `auto_approve_writes` support; classified `filesystem.list` as `LOW` risk.
- `core/runtime/runtime.py`: Added approval confirmation handling in chat; added `init_workspace_structure` and `approve_pending()`.
- `providers/tools/filesystem.py`: Added `resolve_workspace_path` sandboxing enforcement; added `FileSystemListTool`.
- `providers/tools/builtin.py`: Registered `FileSystemListTool`.
- `providers/llm/gemini.py`: Multi-turn tool calling with thought signatures and structured function responses.
- `providers/llm/http_base.py`: Preserved tool metadata in `normalize_messages`.
- `apps/api/main.py`: Added `POST /v1/approve` endpoint; passed workspace and auto-approval settings to `NaradaCore`.
- `apps/terminal/app.py`: Added `/approve` slash command; updated sidebar tools list with `list_dir`.
- `scripts/narada.py`: Added CLI `/approve` handler; enabled `--reload` in development server.
- `tests/agent/test_approvals_flow.py`: Comprehensive test suite for approval states and execution.
- `tests/agent/test_workspace.py`: Comprehensive test suite for workspace sandboxing, categories, and relative path resolution.
- `tests/providers/test_gemini.py`: Deterministic test suite for Gemini multi-turn reasoning with thought signatures.

## Upgrade Guide
Existing users updating to v1.1.0 can pull the latest changes:
```bash
git pull origin main
```
The runtime will automatically provision the `workspace/` directory and subdirectories on first startup.
